# チャット返答にも適用する規則

規則の正本はプラグインルートの `SKILL.md`。ここはチャット返答に持ち込む分だけを抜き出す。
環境変数 `TIRED_DEV_CHAT` が有効なときだけ、SessionStart フックがこの内容を注入する。

持ち込むのは語彙と認知負荷だけである。
どちらも文の長さや口調と独立しており、短く書いても守れる。
要約、見出し、テーブル、検証コマンド、受け入れ条件は持ち込まない。
これらは文書の形式であり、チャットの返答形式を定める別の設定と競合する。

## 語彙

同僚に口頭で説明するときに使わない比喩と英語直訳を使わない。
コード上の実体名、つまりファイル名やパッケージ名で呼ぶ。
説明は日本語で書き、英語の処理名だけで意味を伝えない。識別子や正式なタイトルが必要な場合はそのまま引用し、日本語で動作を説明する。
時刻や情景で状態を言い換えない。「夜 11 時の自分」ではなく「疲れ切った頭」と書く。

| 使わない表現 | 代わりに書く |
|---|---|
| 正典 (canonical) | 正式な定義元、共通パッケージ |
| 写経 | 重複定義、コードのコピー、二重実装 |
| 追補チケット | 追加の対応チケット、別途対応する課題 |
| 直下流 | 直接つながる次のステップ |
| バイト一致 | 完全一致、行単位で同一 |
| ゲートなし | CI チェックなし、自動検査なし |
| 透過合成 | 上流フィールドの引き継ぎ、フィールドの追加マッピング |
| 退避する | 別のファイルへ移動する、削除する |
| ラチェット、楔 | 上限や下限を固定する仕組み、追加する |
| 包括的な、堅牢な、シームレスな | 全ケースを網羅した、例外時も落ちない |
| 効かせる、効く | 適用する |

表にない語でも、比喩か英語直訳だと気づいたら平易な語に置き換える。

## 認知負荷

1. 同一の概念に複数の呼称を使わない。略語は初出で正式名称を展開する
2. 「上記」「前述」「後述」を避け、対象を再掲する。指示語は直前の文の名詞だけを指す
3. 漢字が 6 文字以上つながる複合語と、「の」が 3 つ以上続く修飾を分解する
4. 並列する項目は同じ語順、品詞、文型で書く。体言止めと文末止めを混ぜない
5. 二重否定と否定条件を肯定形に直す
6. 「また」「なお」「さらに」の連鎖が 3 つ以上続いたら、見出しかテーブルに昇格させる
7. 「多くの」「大幅に」「かなり」を使わない。件数、ミリ秒、行数、割合で書く

## 口調との関係

この規則は返答の口調を変えない。
体言止め、助詞の省略、短文への圧縮を求める設定が別にある場合、それをそのまま使う。
語彙の置き換えと認知負荷の低減は、圧縮した文でも成り立つ。
